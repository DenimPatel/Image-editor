Licences and attribution

Everything the Interactive Image Editor ships that is not this project’s own code: 14 self-hosted font files and 19 software packages, with the licence each one is redistributed under. The app’s own code is MIT; that licence does not extend to any of the works below, and this page is the attribution that does.

The build identifier for the running app is shown in the Hub footer and on the crash screen. Quote it in a bug report — it is the difference between a report that can be reproduced and one that cannot.

Two obligations worth reading first

@imgly/background-removal is AGPL-3.0, not MIT

The published package carries the GNU Affero General Public License v3 in its LICENSE.md. It is imported dynamically, so it is fetched only when the Background tool runs, and its model weights are not bundled in this repository — but none of that reduces what a redistributor owes. This is an unresolved decision, not a resolved one; the three options and what each costs are set out in the panel below.

The fonts are OFL 1.1, redistributed unmodified

OFL §2 requires a copy of the licence to accompany every copy of the Font Software, and it ships beside the fonts at /fonts/OFL-1.1.txt. What ships is Google Fonts’ own published latin/latin-ext woff2 subset, byte-for-byte and sha256-pinned, so this project creates no Modified Version and §3’s Reserved Font Name restriction is not engaged. The IE <Family> the Text panel lists is a CSS alias, not a rename of the file. Roboto Mono is the one bundled font under Apache-2.0 instead; its text is at /fonts/Apache-2.0.txt.

An open licence decision: shipping an AGPL library in an MIT app

This page does not choose. It states what is owed.

What is true. @imgly/background-removal@1.7.0 is AGPL-3.0: the package’s own LICENSE.md opens with the GNU Affero General Public License v3, and there is no MIT anywhere in it. It is a runtime dependency of this application, dynamically imported by the Background tool. This application’s own code is MIT; that licence does not extend to the AGPL work linked into the same bundle.

Who owes what. An end user who merely runs the hosted app is a user of the AGPL, not a conveyer — running it is not distribution, so the everyday visitor owes nothing. Anyone who distributes this build is conveying a combined work (this application plus the AGPL library linked into it) and owes the corresponding source under AGPL §5(a). AGPL §13 additionally puts a hosted, modified deployment in scope, so “it only runs on GitHub Pages” is a distribution question, not an exemption.

What is not decided here. The choice between the three options below is an owner’s decision about licensing, hosting and product scope rather than a fact about the tree, so it is recorded here with its costs instead of being quietly resolved in a comment.

  1. Obtain permission. Ask imgly for a commercial licence, for the cut-out to be relicensed, or for an explicit exemption. It may be granted and it may not, on their timetable rather than ours. Until it is in writing the obligation stands. Nothing else in the repository has to change while the request is outstanding.
  2. Replace the dependency. Implement or license background removal another way and drop @imgly/background-removal. This is the only option that ends the obligation by removing its cause. It costs a matting model and a runtime, and the manual background-replacement path that exists today is not a cut-out — it needs a matte to show through, and the matte is what this library produces. The Background tool cannot ship in its current form without it.
  3. Publish the corresponding source. Oblige under §5(a) rather than asking for or avoiding anything: release this application’s complete corresponding source alongside every distribution, including the build scripts and the modifications a recipient makes. This project’s own code is MIT and stays MIT; the AGPL reaches only the combined work. The cost is the ongoing obligation, and the loss of the ability to distribute the build as a closed product.

The accurate statement today is that the obligation exists and is unmet for anyone who conveys this build. “Anyone redistributing this build should read the upstream licence before shipping it” is advice, and advice discharges an obligation under no licence at all.

Fonts

13 of the 14 are SIL OFL 1.1 and one is Apache-2.0. Each is the latin or latin-ext woff2 Google Fonts published, fetched once, verified against the sha256 in models.lock.json and served from this origin; none is fetched from a font CDN at runtime, and none is subset by this project. The Text panel lists them under an IE <Family> CSS alias so its own choices do not collide with a font installed on the machine; that alias is not a rename of the file, whose internal name table still carries the family Google published.

Where this list comes from

The table is declared in src/lib/licenses.ts. Three checks keep it honest, and all three fail rather than warn:

  • Every name in package.json’s dependencies must have an entry, checked by src/components/ui/licenses.test.ts and by npm run assets:check. Adding a dependency without a licence entry fails the build.
  • Every font in models.lock.json must have an entry whose licence matches the lock. The licence strings are copied from the lock rather than retyped, so they cannot drift from the manifest the build already verifies.
  • Every entry in this page. A work that reaches the table but not this document is a test failure, so the user-facing list cannot lag the declaration.

The machine-readable licence texts ship with the fonts, which is what OFL §2 asks for: OFL 1.1 and Apache 2.0.

# Feature Catalogue — Interactive Image Editor

The master map of this codebase. 179 discrete features across nine districts, each with a
status, a priority, a complexity, a file reference and a _concrete test that would prove it_.

This document is the thing `AGENTS.md` mandates. It was first written from six exhaustive
subsystem audits, before any of the work landed, and was then **re-verified line by line against
the working tree** after the implementation pass, and again after the productionisation pass.
Every `Status` in it now means one thing: a named test either exists, or the row says in plain
words that it does not.

Every test file and every named case it points at has been grepped for against the tree as it
stands, and every count in it has been taken from a run rather than from a previous entry. A row
whose proof does not exist is `Untested`; after the 2026-10-01 pass the list of those is exactly
one row — `D9-F05`, this document, which is honest about having no test — and it was already
`Untested`.

The rule that governs every row below is in [section 1.2](#12-status-vocabulary): a feature with
no test is `Untested`, and a removed lie is `Missing`, not `Working`.

## 1. How to read this document

### 1.1 The city

The app is a city. A photo enters at the Customs gate, is decoded at the Border Post, is filed
into the Asset Vault, flows through the Power Plant's pass pipeline, is overlaid by the Atelier,
is measured and framed in the Farmlands, and leaves through the Shipping Yard. The nine
districts below are the city's quarters. Read the City Overview first; it explains the one law
that keeps the city standing.

### 1.2 Status vocabulary

| Status     | Meaning                                                                                 |
| ---------- | --------------------------------------------------------------------------------------- |
| `Working`  | Implemented, and a test exists that would fail if it regressed.                         |
| `Partial`  | Implemented but incomplete, or correct only in some conditions.                         |
| `Stub`     | The plumbing exists (type, default, migration, panel) but nothing executes or produces. |
| `Broken`   | Advertised, wired and demonstrably wrong, or a silent data-loss path.                   |
| `Missing`  | No implementation. The model or the UI copy may reference it; the code does not exist.  |
| `Untested` | Works, but has no test that would fail if it regressed.                                 |

A `Working` feature with no test is `Untested`. Where both apply, the worse status wins — a
feature that is both wrong _and_ untested is `Broken`.

**These six words are the whole vocabulary.** Two rows were written outside it — `Shipped` and
`Open`, which are comments rather than statuses — and both have been folded back in: `Shipped`
rows carry a test that fails without the fix, so they are `Working`, and the one `Open` row is
`Working` for the same reason. A seventh status is the failure mode this section exists to
prevent, and it is not a word in this table.

**A removed lie is `Missing`, not `Working`.** Where a capability was never built and the UI copy
that promised it was deleted, the row is `Missing` and says the claim is gone. Deleting a false
claim is the right outcome; it is not the same outcome as building the thing, and the table says
which happened.

### 1.3 Priority vocabulary

`Pri` is today's work priority, not a record of what the row once was. A row that is `Working`
has nothing left to schedule, so its `Pri` is `—`; that is what makes the Global Status Table
sortable as a work queue.

| Pri  | Meaning                                                                  |
| ---- | ------------------------------------------------------------------------ |
| `—`  | Nothing to schedule: the row is `Working`.                               |
| `P0` | A user-visible lie, data loss, wrong pixels, or a crash. Ship-blocker.   |
| `P1` | A missing advertised capability, or a correctness bug with a workaround. |
| `P2` | Quality, polish, depth. The app works without it.                        |

### 1.4 Complexity vocabulary

| Cx  | Meaning                                                                     |
| --- | --------------------------------------------------------------------------- |
| `S` | Under ~50 lines, one file, no new concepts.                                 |
| `M` | ~50-250 lines, or several files, or a new test harness.                     |
| `L` | A subsystem: new shader, new panel, new pipeline stage, or a new toolchain. |

### 1.5 ID scheme

`D<n>-F<nn>` — district, then a stable sequence. IDs are never reused, even if a feature is
deleted. The Global Status Table (section 5) is the canonical index of 179 rows; each district
table is the place to read the detail and the proof.

The sequence numbers are not contiguous and that is deliberate. `D3-F24` and `D4-F08` do not
exist because those IDs were retired or never issued, and a gap is not an invitation. The second
pass added `D8-F24…F34`, `D9-F15…F19`, `D5-F20/F21`, `D4-F13/F14` and `D2-F16`; nothing was
renumbered to make room, so every ID printed in a test name, a CI comment or an e2e title still
means the row it meant in the first pass.

### 2.2 How traffic flows through the city

1. **Customs gate.** `ImportScreen` accepts a file by picker, drag-drop or paste, validates it
   with `describeUnsupported`, and `Editor.handleFile` decodes it.
2. **Border Post.** `decodeImageFile` (`src/lib/decode.ts`) probes the file's real pixel count
   against `caps.maxCanvasArea` **before** decoding, then calls `createImageBitmap` with
   `imageOrientation: 'from-image'`, so EXIF rotation is baked into pixels. The `ImageBitmap` is
   filed in the **Asset Vault** under a generated `AssetId`.
3. **Asset Vault.** `AssetStore` (`src/model/assets.ts`) is a `Map<AssetId, DisposableAsset>`
   with a `prune`/`clear` GC that closes what it evicts. The `Doc` references the photo only by
   id.
4. **The Power Plant.** Each dirty frame, `planPasses(doc, size, matrix)` (`src/gl/passes.ts`)
   turns the document into an ordered `Pass[]`; `GlRenderer.render` walks it ping-ponging between
   two pooled framebuffers. The source `ImageBitmap` is pulled from the Vault by id and uploaded
   once per bitmap identity, not once per frame.
5. **The Colour Mills** are inside the Power Plant: the tone, colour, curve, HSL and LUT
   fragment shaders, plus the CPU-side `curves.ts`/`hsl.ts`/`auto.ts` that feed and measure them.
6. **The Atelier** composites last, and never on the GPU. `drawLayers` (`src/render/layers.ts:881`)
   runs on the 2D presentation canvas in the preview and on the export canvas at full resolution.
   This is the one design decision in the codebase that buys perfect two-backend parity for every
   layer feature.
7. **The Farmlands** decide the crop and the passport frame _before_ all of that, by writing
   `geometry.crop`, `geometry.aspectLock` and `output.resize`.
8. **The Shipping Yard.** `renderExportCanvas` re-runs the whole pipeline at
   `effectiveOutputSize(doc)`, `encodeDocument` encodes, the DPI/EXIF byte surgery runs, and
   `downloadBlob` fires.

### 2.3 The one law: `Doc` is paper-only

> **`Doc` (`src/model/types.ts`) is a JSON-serializable object. Pixels live in the Asset Vault
> (`src/model/assets.ts`), never in a `Doc` field.**

Every field on `Doc` is a number, a string, a boolean, `null`, or a plain array/object of those.
`Doc.source` is a `SourceRef` — `{assetId, width, height, name, mime}` — not a bitmap. This law
is what makes undo a 50-deep snapshot list, IndexedDB persistence a JSON `put`,
`copy/paste-edits` a string, and context-loss recovery possible at all. It holds everywhere in the
audited tree, and `defaults.test.ts` and `migrate.test.ts` now fail if it stops holding. Do not
break it to store a texture, a canvas or a function pointer; add an `AssetId` and a
`DisposableAsset` in the Vault instead.

The second law, from `AGENTS.md`: a new render pass must work in **both** `src/gl/*` and
`src/render/fallback2d.ts`, or be explicitly feature-gated in `src/gl/caps.ts`.

**That law was broken in roughly thirty places when this catalogue was first written. It is no
longer broken.** The Canvas2D backend now runs the same pipeline as the GL backend — it is not a
thin `setTransform` and `ctx.filter` shim any more — and `src/render/fallback2d.test.ts` and
`src/render/parity.test.ts` hold the two to within about 2/255 per channel per pass family. The
only gated pass is `lut3d`, which Canvas2D cannot express; the gate is declared in
`src/gl/caps.ts` rather than discovered at runtime. A verifier pass also found and fixed a
separate Canvas2D bug in which the preview read its own output canvas back as scratch, producing
a near-blank frame whenever the source was larger than the output.

## 3. Districts

### D1 — Foundation District (`src/model/`)

#### District brief

This is City Hall. `Doc` is the only constitution: a flat object that every other subsystem reads
and none of them may mutate directly. The Survey Office (`defaults.ts`) mints the canonical
neutral document and the `ADJUST_SPECS` table that both the UI dials and the auto-exposure code
measure themselves against. The Registry (`migrate.ts`) is the only door through which foreign
JSON may enter, and its job is to normalise, never to reject. The Asset Vault (`assets.ts`) is
the single owner of every `ImageBitmap` in the process and the reason a document can be
`JSON.stringify`-ed without incident. The district's original failure mode was _silent_ leniency:
the Registry accepted numbers, colours and layer objects it should have rejected, so a hand-edited
recipe or a corrupted session row became an app that rendered orange backgrounds and one-pixel
exports rather than an error. It now normalises hard, and the normalisation is tested.

### D2 — Transit & Records (`src/store/`, `src/lib/persist/`)

#### District brief

This is Undo Parkway plus the Registry that remembers what you were doing. `src/store/history.ts`
is a pure engine, deliberately free of React and zustand, and it is the best-tested module in the
repository. The trouble was never the engine; it was the **callers**. Roughly a third of the UI
used to write to the document through actions that passed no coalesce key and opened no
interaction, so a two-second slider drag burned all fifty undo slots. Every one of those callers
now brackets its gesture, and `actions.ts` folds multi-field actions into a single undo step.

The Registry half of the district has a residual that is worth reading twice: autosave is now a
debounce with a `pagehide`/`visibilitychange` flush, but an async IndexedDB write cannot complete
during teardown, so a hard reload within about 150 ms of an edit still loses that edit. That is
`D2-F11`, and it is a real `Partial`, not a `Working`.

### D3 — Power Plant (`src/gl/`, `src/render/`)

#### District brief

`planPasses` is a pure, well-tested function producing an ordered `Pass[]`, and the design is
genuinely good — one projective geometry resample instead of a rotate-then-crop double blur,
ping-ponged framebuffers from a pool, a leading pass that absorbs the Y-flip exactly once. What
used to go wrong at the seams has been fixed: the geometry matrix is uploaded with the transpose
flag the driver needs, the source bitmap is uploaded once per identity, one long-lived export
renderer replaced the per-tick context, and the Canvas2D backend now runs the same pipeline.

Three defects in this district were found **only** by a real GPU, and they are worth reading
together because they are three different ways for a pipeline to be confidently wrong: the
framebuffer format the pool allocated, the matrix transpose (`D3-F03`), and a shader that did not
compile at all (`D7-F04`). jsdom has no WebGL context, so none of the three was reachable from
the unit suite — not by writing the wrong test, but because the environment does not exist. All
three now have gates: `e2e/shader-compile.spec.ts`, `e2e/shader-parity.spec.ts` and
`renderer.matrix.test.ts`. See the changelog.

`D3-F23` — ordered dither and a filmic shoulder — is the district's one piece of deliberate
colour science, and it is `Working` because both halves are measured against the bytes the app
really ships rather than against the recipe. One row is still open: `D3-F25`, a wasted
subscription rather than a wrong frame.

### D4 — The Colour Mills (`src/gl/shaders/`, `src/lib/curves.ts`, `hsl.ts`, `auto.ts`)

#### District brief

Three rooms. The **Glassworks** is `curves.ts`: a Fritsch–Carlson monotone cubic Hermite

six dial positions.

does not produce "five perfectly correlated outputs". `brightness` and `shadows` are 0 on the
reference image by measurement, and `auto.test.ts` pins the independence.

### D5 — Farmlands (`src/lib/crop/`, `src/features/passport/`)

#### District brief

Geometry is the product. Seven coordinate spaces run from source pixels to cropped output, and a
single projective matrix (`src/gl/geometry.ts`) collapses all of them into one resample — the
best idea in the codebase. The Fence-Line Survey used to be where it fell apart: aspect ratios
were computed in _normalized_ space, so a 3000×2000 source locked to "1:1" produced a 3:2 pixel
rectangle, and the function was shrink-only with no anchor, so dragging a handle outward slid
the crop sideways instead of growing it. Both are fixed and both are measured in pixels now. The
ID Photobooth is the other half of the district, and its rule is the same as the rest of this
catalogue: a checker that cannot fail is a decoration, so every rule is labelled `measured` or
`assumed` and the assumed ones are named as such.

### D6 — The Atelier (`src/features/layers/`, `src/render/layers.ts`)

#### District brief

Layers never touch the GPU. `drawLayers` (`src/render/layers.ts:881`) composites all seven kinds
— text, sticker, shape, draw, redact, watermark, frame — onto a 2D canvas after the Power Plant
has finished, in the preview at proxy size and in the export at full resolution. That is why every
layer feature has perfect parity between the two backends; it is the best architectural decision
in the repo.

This district was a list of broken promises, and the redaction work closed two real privacy leaks
rather than two cosmetic ones. An emoji redaction drew no cover and shipped the secret
_underneath_ the emoji, and `LAYER_TRANSFORM_PARTS` exposed Opacity and Blend for `redact`, so a
redaction could be made see-through. Both are fixed, and the proof needs no threshold: export
twice with two different secrets under an opaque redaction and the two exports are
byte-identical.

### D8 — Piazza & Civic Buildings (`src/components/`, `src/pages/`, `src/styles/`)

#### District brief

This is everything a person touches. The editor is a vertical flex stack, `position: fixed;
inset: 0`, with a CSS-switched bottom sheet that becomes a right-hand inspector at 900 px. Four
of the top five layout bugs were in that one mechanism, and all four were
`BottomSheet.tsx`. The accessibility posture is now the strongest part of the app: the curves
editor has focusable points, arrow nudge and `Delete` instead of a misleading
`role="application"`, the crop handles are real sliders that announce a value and do something,
and `e2e/a11y.spec.ts` runs axe over WCAG 2.1 A/AA with an **empty** allowlist.

The second half of this pass is not about ARIA at all. It is the claim that the things on screen
are the things in the code: a ratio you can recognise without reading it (`D8-F26`, `D5-F20`), a
layer named by what it is rather than by its id (`D8-F27`), a panel that explains itself when it
is empty (`D8-F28`) and says what went wrong when it is not (`D8-F29`), an accent you can change
and a text size your browser can change too (`D8-F18`, `D8-F24`, `D8-F25`). **Every row in this
district is `Working`, which is not a claim of perfection — it is the first district in the
catalogue with no open rows at all**, and that is only true because the last three of them
(`D8-F20`/`F21`/`F22`) were sitting in the index with no district row and no proof at all until
this pass gave them one.

### D9 — Utilities & Sanitation (`src/hooks/`, `src/lib/`, `scripts/`, `.github/`, build config)

#### District brief

The district of things that touch everything and belong to nothing. This is also the district
where the _verification_ story lives, and the story has changed completely: there is now a
Playwright suite of **623 cases across 38 spec files** on Chromium, WebKit and a mobile project, a
coverage configuration with per-area thresholds, a CI format gate, an axe a11y gate with an empty
allowlist, a shader-compile suite that compiles every exported shader on a real GPU, a
shader-parity suite that compares the real GLSL against the CPU twin, and route-level code
splitting.

The second half of this district is the difference between software that works and software a
person can get help with when it does not. **A build that says which build it is** (`D9-F15`), so
a bug report names a commit instead of "latest". **A diagnostics buffer that cannot phone home**
(`D9-F16`), because the product's central claim is "nothing leaves this tab" and the usual way to
add bug reporting is a network call — which would make the claim false in the one module whose
whole job is to be believed. **Four debug switches** (`D9-F17`) for a static host with no backend,
so a user whose GPU driver is the problem has somewhere to go. **A runtime frame budget**
(`D9-F18`), because `check-bundle.mjs` answers "how much JavaScript does a visitor download" and
nothing here answered "what does the app do once it is running". And **a byte budget for
`public/`** (`D9-F19`), because a gate that asks whether the files it knows about exist cannot
notice a file nobody declared.

## 4. Cross-cutting findings

Four defects were not one feature each; they were the reason the other defects were hard to see.

1. **The two backends disagreed, and nothing knew.** `src/render/backend.ts` presents one interface
   to two implementations, and `src/gl/caps.ts` had no per-pass feature flags. Every parity bug
   in D3 was invisible to the test suite because the suite only tested whichever engine the stub
   happened to be. `D3-F10` is fixed and the parity harness that keeps it fixed is
   `src/render/fallback2d.test.ts` plus `src/render/parity.test.ts`. The one remaining gated
   pass, `lut3d`, is declared in `caps.ts` rather than discovered at runtime.
2. **The UI lied, and the lies were the defects.** `ToolSurface.DESCRIPTIONS` and
   `BackgroundPanel` described face auto-detection, a repair brush, pressure-aware marker and
   highlighter brushes, text arc, sticker uploads, layer rename and layer blending. Most of them
   now exist and are tested. One did not and cannot cheaply: the repair brush (`D6-F11`) had its copy
   deleted and is recorded `Missing`; the on-canvas transform handles (`D6-F14`) were built and are
   recorded `Working`; face
   auto-detection (`D5-F13`) was replaced by an honest "Auto-frame the head" wired to
   `measureCanvas` → `autoFrame` → `setCrop`.
3. **The repo's own documentation was part of the bug surface — and the biggest offenders were
   the ones only a real browser could find.** `README.md` claimed shader correctness "is
   exercised separately" and listed it as roadmap, promised straighten auto-zoom, promised a
   transparent PNG mode, promised LUTs and self-hosted fonts it did not ship, and said A5 where
   the code had A3. All of that is now either true or deleted. But the five worst defects of the
   two passes — the black WebGL preview, the transposed `mat3`, the GLSL compile error that broke
   every export with a background, the inspector covering the top bar, and the histogram scaled
   against a blown-sky plateau — were in **code**, not copy, and not one of them was reachable from
   jsdom. See the changelog for the mechanism in each case.
4. **A row with no test is indistinguishable from a row with a test nobody read.** This is the one
   that bit this document. `D8-F20`, `D8-F21`, `D8-F22` and `D8-F23` sat in the Global Status
   Table for a whole pass with a name and no proof column, and the header's own count was eight
   rows short of the table, so nothing about the document's shape disagreed with anything. A
   catalogue needs the same treatment as the code: **the index and the detail must be checkable
   against each other**, and a number in a header is a claim like any other.

## 7. Verification Protocol

A feature is proved when the named test exists **and fails before the fix**. Three levels, and
the third one is the contract for UI work.

### 7.1 Pure logic → a sibling unit test

Anything in `src/model/`, `src/lib/`, `src/store/`, `src/features/*` that is a pure function gets
`src/<sibling>.test.ts`, jsdom environment, no React, no mocks beyond what the module takes as
parameters. The test states the _contract_, not the implementation: pass a fixture, assert the
value, assert the boundary. `AGENTS.md` invariant 3 (history stays pure) and invariant 5 (pure
logic lives in `src/lib/*`) both exist to make this possible.

```
export PATH="$HOME/.nvm/versions/node/v24.21.0/bin:$PATH"
npx vitest run src/lib/curves.test.ts
```

### 7.2 Render passes → both backends, or a `caps` flag

A render feature is only proved when it is proved on **both** engines: one fixture `Doc` through
the GL backend and through the Canvas2D backend, held to about 2/255 per channel per pass family.
Where parity is genuinely impossible — a 3D LUT lookup on a Canvas2D backend — the pass is gated
in `src/gl/caps.ts` and the UI shows the degradation, rather than the two engines quietly
disagreeing. For pure-shader work, the real proof is a GPU test: `e2e/shader-compile.spec.ts`
compiles every exported shader, and `e2e/shader-parity.spec.ts` compares the real GLSL against
`runCpuPasses` in a real WebGL2 context. **That parity suite skips on a software rasteriser
(SwiftShader, llvmpipe) and records the renderer string in its report**, so a skip can never be
mistaken for a pass.

### 7.3 UI and interaction → Playwright

**The e2e suite is the contract for UI work.** `AGENTS.md` says "UI/interaction features need a
Playwright check", and that is now enforceable because Playwright is installed. The required
shape, from `e2e/fixtures.ts`:

- Build on the `test` from `e2e/fixtures.ts`. Do not write a raw `import { test } from
'@playwright/test'` in a new spec; the fixtures are the contract.
- Locate by **accessible name or role**, never by a CSS-module class.
- Assert on the live store (`readDoc()`) or the stored row (`persistedDoc()`), never on a value
  copied into the test.
- Assert on the **bytes** of a download via `readImageHeader`, never on "not empty".
- `npm run test:e2e` starts its own dev server on **port 5317**, so it never collides with a dev
  server already open on 5173. Do not stop that one.
- **Never let a test download the matting model.** `@imgly/background-removal` pulls ~42 MB
  from a CDN; the matting test is behind `E2E_MATTING=1` and is off in CI.
- **623 cases in 38 spec files** run on Chromium, WebKit and a `mobile` project with `hasTouch`.
  The mobile project's `testMatch` is `/journey\.mobile/`, which is **two** specs —
  `journey.mobile.spec.ts` and `journey.mobile-touch.spec.ts`, 19 cases — and the other two projects
  `testIgnore` that pattern. All three projects are matrix legs in `ci.yml`. Every skip has a named
  reason — no WebGL2 context, no `WEBGL_lose_context`, no real GPU (which records the renderer
  string), WebKit aborting the IndexedDB blob write, Safari not tabbing to links, not the matrix
  engine for that spec, and `E2E_MATTING=1` for the one spec that would download 42 MB.

### 7.4 Commands

```bash
export PATH="$HOME/.nvm/versions/node/v24.21.0/bin:$PATH"

npm test                 # vitest run (jsdom, pure/unit) — 2974 tests in 148 files
npm run test:coverage    # vitest run --coverage, enforces the per-area thresholds
npm run test:e2e         # playwright test: chromium + webkit + mobile, own dev server on 5317
npm run typecheck        # tsc -b
npm run lint             # eslint .  (must be clean)
npx prettier --check .   # repo-wide; green today
npm run build            # assets:check && tsc -b && vite build && check-bundle && check-public-budget
npm run dev              # vite dev server, prints local URL

npx vitest run src/gl/passes.test.ts   # scope to one file
npx vitest run --coverage              # per-area thresholds
npx playwright test                    # the UI contract
```

Do **not** use `-u` / `--update` on snapshots unless the change is intentional; a silent snapshot
update is how a rendering regression becomes the new expected output.

A gate must be green on the branch that adds it. The coverage thresholds and the CI format gate
were both scoped to what actually passes, and the reasoning is in `vite.config.ts` and `ci.yml`.

## 9. Maintenance

- **Update this file in the same commit as the change.** `AGENTS.md` requires it. A feature that
  changes status without a row change here is a change nobody can audit.
- **A row's `Status` is a claim about a test, not about the code.** If you cannot name the test,
  the row is `Untested`. If you delete a claim instead of building the feature, the row is
  `Missing` and says the claim is gone. Both are respectable outcomes; a `Working` row with no
  test is not.
- **Never reuse an ID.** If a feature is deleted, its row goes to a `Removed` note in the district
  section and the ID is retired. The Global Status Table is a stable index.
- **Every new render pass** needs a row, a `Caps` entry if Canvas2D cannot express it, and a
  `parity.test.ts` case. That is the mechanism that stops the next `D3-F10` from happening.
- **Every new UI string that promises a capability** needs a feature row _first_. If it cannot be
  found in the Global Status Table, the string is a defect.
- **jsdom has no WebGL.** Any claim about what a shader does is unproven until a real GPU has run
  it. See `D3-F03` and the changelog.

### The bugs of this pass, by mechanism

The argument this document keeps making is that these classes of defect are **invisible to unit
tests** — not because the tests were bad but because the environment in which the defect lives does
not exist in jsdom. Six more, and the mechanisms are different in each case.

1. **The desktop inspector covered the top bar and all thirteen tool tabs.** At 1280×900 the sheet
   was laid out over the chrome rather than beside it, so the controls a person needs in order to
   change tool sat underneath a panel, unreachable by pointer and unclickable by keyboard. The
   mechanism is worth stating precisely because the fix is not "raise the z-index": `.sheetBackdrop`
   was `position: fixed`, which resolves against the **viewport**, not against the canvas region. A
   fixed-position scrim inside a flex child covers everything the child can see and then some.
   Scoping it to `position: absolute` inside `.canvasRegion` fixed the chrome — and immediately
   exposed the next defect, below. The remaining half needed structure rather than a box: a **grid
   column**, `grid-template-columns: minmax(0, 1fr) var(--ie-inspector-width)`, with the width token
   deliberately outside the sheet's own box model because a grid column cannot be expressed as a
   sheet property. `e2e/journey.inspector-layout.spec.ts` is the gate; `D8-F33`.
2. **The phone sheet's backdrop killed every canvas control.** Scoping the scrim to the canvas region
   fixed the bars and left the whole canvas under it — and `.canvasRegion` on a phone _is_ the box
   between the two bars, so a scrim that takes pointer events is a scrim over the entire visible
   canvas. All eight crop handles, all five layer transform grips and the crop box's own move
   gesture were dead for exactly as long as a panel was open, which is the whole time you want them,
   and a thumb aimed at the se handle closed the panel instead of dragging the crop. Two of thirteen
   tools could not be used on a phone at all. **The fix is `pointer-events: none` on the backdrop**,
   which is counter-intuitive and correct: a scrim that dims and cannot be pressed is a picture of a
   scrim, and dismissal already has three other doors (a 44 px Close, Escape, and any other tool tab
   — which is why the tab bar is deliberately left lit and tappable). This is the same defect class
   as (1) with one fewer layer of nesting, which is why a unit test that asserts a CSS rule exists
   proves nothing about either.
3. **`readDoc` was importing a second, empty store on a warm dev server.** Every journey assertion in
   the e2e suite reads the live document through `readDoc()`, which does a dynamic `import()` in page
   context against a URL derived from `document.baseURI`. On a cold Vite dev server the bare
   specifier `…/src/store/docStore.ts` and the URL the app actually imported are the same module, so
   the dynamic import resolves to the same instance and the same zustand store — and every assertion
   is about what the editor really did. On a **warm** server they can differ: the app may have been
   served `/src/store/docStore.ts?t=…` after an HMR update, the bare import gets a **fresh module
   instance**, and `useDocStore.getState().present` in that instance is a default document. It is
   not an error: it returns a truthy default doc, so the `!doc` guard never fires, and every
   assertion downstream is made against an empty editor while the screenshot beside it shows the
   real one. **A gate that fails silently and only on the second run of a dev server is worse than no
   gate, because it teaches the next person to trust the wrong number.** The fix reads the live URL
   out of `performance.getEntriesByType('resource')` and imports _that_, falling back to the bare
   path only for a page served with no module graph. Every journey assertion depends on it; none of
   them could have been trusted before.
4. **Eight chips lit for one 1:1 crop, and `Doc` records no platform at all.** The crop panel's
   platform rows were made selectable by lighting a chip whose _pixel aspect_ matched, on the
   reasoning that seven of the presets are 9:16 and therefore all seven were honest. They were
   honest and the panel was still broken: a 1:1 crop lit seven chips in the platform block plus the
   generic `1:1` above them, which a first-time reader counts as eight things selected — and the
   lights went out again the moment a handle moved the box a pixel, a gesture nobody thinks of as
   un-selecting anything. The mechanism is a **modelling** gap, not a styling one:
   `geometry.aspectLock` stores a number, not a preset id, so there is nothing in the document that
   could record where the ratio came from, and a chip lit on a derived property was claiming state
   the document does not have. Lighting only the tapped chip was rejected — it needs the tap
   remembered in component state, which dies with the panel and is wrong after a drag — and plain
   buttons were rejected because 22 of them announced as plain buttons 200 px below the one control
   that _is_ pressed is a worse story than an honest toggle group with nothing toggled. So the
   platform rows hold **no** selection and the generic row holds all of it: one lit control in the
   panel, in the row whose labels are the shapes themselves. `D5-F20`.
5. **Six of the twenty-four looks were the same look twice.** Every pair of the catalogue was graded
   through the thumbnail scene and asserted 12/255 RMS apart, with the floor justified by a
   measurement rather than a comment (a 0.10 move on one of a look's own knobs measures 4.5 at 0.05
   and 8.6 at 0.10). Before: `Vista`/`Faded Matte` **4.51**, `Polaroid`/`Vintage Fade` 4.74,
   `Superia`/`Vista` 4.98, `Faded Matte`/`Pastel` 6.50 — six looks inside 8, on chips that are
   presented as 24 different looks and are read as such. The mechanism is that a LUT preset is
   `{ id, label, family }` with **no colour data in it** (`D4-F05`), so nothing in the model can
   tell you two of them are near-identical; only a measurement over the grade can, which is why
   `lut-looks.test.mjs` measures rather than hashes. Shipped tree: no pair below 13.3. `D4-F24`.
6. **A retouch tab whose honest "not built yet" copy sat under an affordance that looked like a peer
   of Crop.** The passes were correct and both engines ran them; `Doc.retouch` had a default, a
   migration and a pass planner entry and **no producer**. So the `retouch` tab — a real tab in the

### 2026-09-30 — local diagnostics: a bug report a user can actually send

The gap this closes is the worst one a product can have: nothing to report with. A white
screen produced a `console` tab and a sentence. `ErrorBoundary` declared an `onError` prop
and no caller passed one, there was no `window.onerror`, no `unhandledrejection` and no
`console.error` capture, `useRenderLoop`'s `catch {}` swapped the editor onto Canvas2D with
no word at all, and every toast was gone 3.2 seconds after it appeared — so
_"Storage is full — this session was not saved"_ was the only evidence of a lost session, and
it lasted three seconds.

**`src/lib/diagnostics.ts`** is a bounded ring buffer — 100 entries **and** 64 kB, whichever
binds first — fed from `window.onerror`, `unhandledrejection`, a `console.error` _wrapper_
that always calls the original through, `ErrorBoundary`'s `onError` and the render fallback.
Per-tag counts live outside the ring, so "this threw 4,000 times" survives the eviction.

**The privacy boundary is a mechanism, not a promise.** An entry is a fixed shape of strings;
a caller contributes either a string or a real `Error`, and only `name`, `message` and `stack`
are read off one. Everything else — `File`, `Blob`, `ImageData`, `Doc`, canvas, `Proxy` — is
reduced by `describeUnknown` to a _type name in brackets_, with no serialisation and no
property read anywhere in the path. `diagnostics.test.ts` feeds all four carriers through
every feed path and asserts none of their content reaches the buffer or the report, and
asserts the source contains no `fetch`, `XMLHttpRequest`, `sendBeacon`, `WebSocket`,
`EventSource` or dynamic `import`.

**Getting the text out.** "Copy diagnostics" on the crash screen (inside the technical-details
disclosure) and in the Help overlay: clipboard API first, a hidden field plus
`execCommand('copy')` on a refusal, and — if that is gone too — the text selected on screen
with the keys to copy it named. "Copied" is never claimed unless it happened.

**Error toasts are kept.** Error severity alone, 20 entries, a week, versioned, and deleted by
the reader with one button — it lives in their `localStorage`.

**The silent fallback now says so, once:** _"A frame failed to render, so the preview is now
using the slower renderer. Your edits are unaffected and still save. Reload the page to try the
faster renderer again."_

**Two privacy leaks closed, in `D6-F05`.** Both shipped real user data underneath a control that
claimed to hide it.

1. **Emoji redaction was cosmetic.** The emoji tiles drew no cover, so the secret shipped
   _underneath_ the emoji it was supposed to be hiding. Solid and emoji redactions are now
   byte-identical under the same test.
2. **A redaction could be made see-through.** `LAYER_TRANSFORM_PARTS.redact` exposed Opacity and
   Blend, so a user could set a redaction to 40 % and export the thing it was hiding.

The proof needs no threshold: `e2e/journey.redaction.spec.ts` exports twice with two different
secrets under an opaque redaction and compares a SHA-256 of the band. The two exports are
identical. Two more cases pin that a redaction offers no way to become translucent and that a
document carrying a translucent one still exports opaque.

**Three bugs that only a real browser could find.** jsdom has no WebGL context at all, so none of
these three was reachable from the unit suite — not by writing the right test, but by the
environment simply not existing.

1. **A black WebGL preview, caused by an FBO type mismatch.** The render targets were allocated
   with a different type than the pipeline wrote into them, so the preview canvas presented an
   empty buffer. The unit suite passed because the fake GL does not care about framebuffer
   completeness; a human looking at the app did.
2. **The `mat3` transpose that made every crop, rotate, flip and straighten wrong.** The matrix
   was uploaded with `transpose = false`, so the GPU computed `Mᵀ·p`. Cropping — the single
   most-used feature in a photo editor — produced an un-cropped image on any WebGL2 device while
   being correct on Canvas2D, so the two backends disagreed in the one way nobody was checking.
   `renderer.matrix.test.ts` now resolves every probe point against `applyMat3`.
3. **A GLSL compile error that broke every export with a background.** One line, one type error,
   and the entire background path failed to compile — so every document with a background
   exported nothing usable. `e2e/shader-compile.spec.ts` now compiles **every** exported shader
   on a real driver, which is the gate that makes that class unable to ship again.

**A fourth, found by a verifier rather than a browser:** the Canvas2D preview read its own output
canvas back as scratch, producing a near-blank frame whenever the source was larger than the
output. Canvas2D is a second implementation of the same pipeline, which means it is a second
place for exactly the bugs above. **Two more arrived with the productionisation pass on
2026-10-01** — the inspector covering the top bar, and the histogram's plateau ceiling — and both
are written up there.

**Refuted in the code.** The original D4 brief claimed `auto.ts` produced "five perfectly
correlated outputs" from a single gamma-space mean. It does not: `brightness` and `shadows` are
0 on the reference image, and `auto.test.ts` pins the independence. `AUTO_BLOWN_LEVEL` is now a
dedicated constant measured on the source histogram, because the old threshold called a clean
bright sky "blown" and greyed it.

**Also corrected:** the claim that the Canvas2D fallback is "broken in 30 places — see `D3-F10`".
`D3-F10` is fixed; the fallback now matches the GL pipeline to within ~2/255 per pass family with
`lut3d` the one gated pass. The 140-feature count became 145 when `D7-F18` and `D7-F19` were given
rows in the D7 table; both are now in the Global Status Table too.
